# Pushing AgniUI to `sriram-e-automation/agni-ui`

The repo is newly created and empty. This folder is the scaffold that turns the design system into a publishable package — everything a repo needs that a design-system project doesn't have. Copy it to the repo root, drop the sources in beside it, push.

The concepts behind all of this — registries, scopes, why GitHub Packages — are in [`PACKAGING.md`](../../PACKAGING.md). This file is just the moves.

---

## What's here

| File | Why |
| --- | --- |
| `src/index.ts` | **The public surface** — 110 values + 206 types, generated from the `.d.ts` contracts. Anything not exported here is internal, which is how `ButtonBase`, `IconButton`, `SplitButton` and the other retired renderers stay reachable inside the library while being absent from the published API. |
| `package.json` | Name, exports map, peer deps, `publishConfig` pointing at GitHub Packages. |
| `vite.config.ts` | Library build. React is `external` — two copies of React in one page break hooks with an error that reads like nonsense. |
| `tsconfig.json` · `tsconfig.build.json` | Type-check, and emit `.d.ts` into `dist/`. |
| `.changeset/` | Changesets config + the note on how to write one. |
| `.github/workflows/ci.yml` | Type-check, build, and **fail a PR that changes `src/` without adding a changeset**. That check is what makes the SOP hold. |
| `.github/workflows/release.yml` | The release bot. Merge a PR with a changeset → it opens a "Version Packages" PR → merge that → it publishes and tags. |
| `.github/pull_request_template.md` | The four-check review gate from `CONTRIBUTING.md`, as a checklist. |
| `.gitignore` · `.npmrc.example` | `.npmrc` is git-ignored here; the example is for consuming apps. |

## Step 2 — make it compile

The sources here are written for a compiler-less browser environment, so two things need adjusting once, and only once:

1. **Import extensions.** Components import each other as `"../core/Button.tsx"`. Vite is fine with that, but it is unconventional in a package — strip the extension repo-side if you want clean imports. Either works; don't do it halfway.
2. **`strict: true` will find things.** The three new grouped components (`RecordTable`, `ApprovalPanel`, `StatsOverview`) take `props: any` because the design-system project has no type-checker. Their `.d.ts` files carry the real contract — port those signatures into the `.tsx` on first compile. Everything else is already typed.

```bash
npm run check    # expect work on the first run, then clean
npm run build
npm pack --dry-run   # must list dist/ only — no cards, no audits, no uploads
```

## Step 3 — first push

```bash
git add -A
git commit -m "feat: AgniUI 1.0.0 — initial import"
git push -u origin main
```

Then in GitHub: **Settings → Branches → protect `main`** (require a PR, require CI green, require one review). The SOP in `CONTRIBUTING.md` assumes this; without it, the changeset check is advisory.

## Step 4 — first publish

The release workflow runs on every push to `main`, but it only publishes when there is a changeset to consume. For the initial `1.0.0` there isn't one — publish it once by hand:

```bash
npm run build
NODE_AUTH_TOKEN=<your PAT with write:packages> npm publish
```
