Form layout — the field grid

Every create/edit form is a single-column stack of titled sections inside a centred Panel that rises from the bottom. Dense sections use a 2-up field grid that collapses to one column on narrow viewports. The cadence is driven entirely by --field-* and --sheet-* tokens, so every form shares one rhythm.

1 · Panel anatomy
Sticky header — title + close --sheet-header-h 60px
Scrollable body — section stack, padded --sheet-pad-y / --sheet-pad-x (20 / 24)
Sticky footer — Save as draft · Submit --sheet-footer-h 68px

Header and footer never scroll; only the body does. Max width is capped at --sheet-max-w 880px and centred, so the form stays readable on wide screens.

Columns are repeat(auto-fit, minmax(var(--field-min), 1fr)) — they pack 2-up while there's room for a --field-min 260px column, then wrap to 1-up. Wide controls (textareas, tables, file zones, the user picker) span the full row with grid-column: 1 / -1.

4 · Layout fundamentals
Group fields into titled sections; separate them by --field-section-gap, never ad-hoc margins.
Mark every mandatory field with the * and repeat the legend in the footer.
Let wide controls span the full row; keep short, related inputs side-by-side.
Keep actions in the sticky footer — primary right, draft beside it, legend left.
Don't fix the grid to 2 columns — it must collapse below --field-min.
Don't scroll the header or footer; only the body region scrolls.
