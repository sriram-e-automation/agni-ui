Page blocks — the eight groups

A module page in this ERP is assembled from eight composed components, not from forty primitives. Each one owns a region of the page, composes existing DS parts rather than redrawing them, and exposes everything inside it through props. Reach for a primitive only when a page genuinely does something no block covers.

A group adds no new visual vocabulary. If a group draws something a component could have drawn, that is a missing component, not a group feature.

Page anatomy

PageHeaderthe two rows below, in one card — mount this rather than the pair
PageTitleBarback · icon + title + status badge · subtitle · scope tabs with counts · view switcher · export / secondary / primary actions

ActionSpec — one action contract, every group

Every group takes primaryAction, secondaryActions and exportAction as data, not as JSX. That is what lets a group role-gate, size and disable its own actions instead of trusting each page to do it the same way. The actions ReactNode slot survives on every group as the escape hatch, rendered after the declarative set.

interface ActionSpec {
  key?, label, icon?          // icon is a Phosphor class: "ph-plus"
  kind?    // "primary" | "secondary" | "tertiary" | "ghost" | "danger" | "brand-soft"
  size?    // "sm" | "md" | "lg"
  iconOnly?, round?, active?
  disabled?, disabledReason?  // reason becomes the tooltip while disabled
  loading?, hidden?
  items?                      // secondary choices → Button's split treatment
  roles?                      // core/RoleGate contract; omit to always show
  onClick?
}
interface ExportActionSpec {
  enabled?   // default true. false → VISIBLE but disabled, with disabledReason
  formats?   // 2+ → split menu; 1 → plain button; 0 → plain button, no format arg
  loading?, label?, icon?, kind?, iconOnly?, roles?
  onExport?(formatKey?)
}

Three decisions inside these props, and why

DecisionReasoning
A withheld export is disabled, not hidden.A records page that changes shape per viewer looks broken to the person who asks why their colleague has a button they don't. enabled: false keeps it in place with a reason on hover. Omit the prop entirely only when the page genuinely has no export.
A withheld row action column is hidden.The opposite call, for the opposite reason: an action column that renders empty for every row is a column of whitespace advertising nothing. If a viewer's role matches no row action, RecordTable drops the whole trailing column.
Row actions may be a function of the row.Availability usually depends on the record, not only on the viewer — an approved request cannot be approved again. rowActions={row => […]} keeps that logic beside the action instead of in a wrapper.

Pairing rules

WhenThen
PageTitleBar and PageControls are both on screenMount PageHeader, which owns the card shell and enforces the next rule for you.
Both rows carry a view switcherThe title bar owns it. PageHeader drops any viewModes passed to controls; mounting the pair by hand, do not pass it.
The page has a quick-stats stripPageHeader stats={…} — the toggle renders in the toolbar's leading slot and the strip's open state is the header's, not the page's.
Using RecordTableDo not also mount PageControls or Pagination — RecordTable owns both. Pass them through controls and pagination.
The approval sits on a record pageApprovalPanel. Over a list, RecordDetailModal. They read the same three parts, so they cannot drift.
A page needs one bespoke controlUse the group's actions / leading slot. Do not fork the group.
